Requirements reference

Requirements may be flat or grouped into payload, workspace, rotations, and optional constraints. Nested payload, workspace, and rotations must be objects containing their required fields. In the grouped format, constraint keys may also sit at the top level and are merged into constraints; a key present in both places is rejected. Both formats use the same validation. Errors identify the invalid field before evaluation begins. Numeric strings and null values are rejected, including optional sub-fields (only per_servo_ratings entries may be null); omitting an optional field uses its default.

Ranges and defaults

Ranges accept [min, max], { "min": min, "max": max }, or { "from": min, "to": max }. Arrays must contain exactly two values. Equal bounds are allowed for a fixed length, stationary coordinate, or locked servo. A zero payload removes the modeled external load; zero stroke or frequency evaluates a stationary cycle. Valid input need not describe a feasible design.

The parser initializes grid steps that produce three samples along each nonzero workspace or rotation range (min, midpoint, max). Zero-span ranges contain one grid sample. The default Halton strategy uses the bounds and ignores steps; select 256, 1,024, or 4,096 samples, or select Cartesian grid. Explicit UI overrides, including home-height bounds, take precedence over JSON defaults; untouched controls follow edits to the JSON. Loading the sample resets range and height controls. UI steps must be positive; population and generations must be integers ≥ 4 and ≥ 1 respectively. Workload limits apply independently of physical input validation.

Servo ratings

A per-servo value overrides the shared value for that servo and metric; an omitted per-servo value inherits the shared value. The UI rating fields use the JSON values as defaults. Edited UI values take precedence for the run; untouched fields refresh after JSON edits. Loading the sample resets rating controls. Clear a UI field to remove that rating. Speed ratings entered in deg/s are converted to rad/s for comparison with cycle demand. The UI edits shared peak torque, speed, continuous torque, policy and per-servo peak torque/speed; curves, duration ratings and actuator models come from the JSON and are kept when UI per-servo fields are edited. Ratings do not change the force-balance or servo-speed models; an actuator model adds its terms to the compared actuator torque.

Layout format and units

A downloaded Layout JSON works as-is. For a hand-written layout, provide these fields:

  • base_anchors and platform_anchors: six [x, y, z] coordinates each, in millimeters.
  • beta_angles: six servo angles, in radians.
  • horn_length, rod_length, and home_height: positive lengths, in millimeters.
  • servo_range: [minimum, maximum] angles, in degrees.

All numbers must be finite. If you include a topology, its parameters must match the supplied geometry. Imported scores are recalculated using the current requirements.

Servo ratings

Optional capacity limits. Speed is entered in degrees per second and compared with cycle demand in radians per second. Per-servo values override shared values. Continuous torque is compared with time-weighted RMS cycle torque, a screening metric rather than a thermal prediction. Torque-speed curves, duration-limited ratings and actuator inertia/friction are set in the requirements JSON.

Translations are millimetres; rotations are degrees. Arrow keys move X/Y, Page Up/Down moves Z, W/S and A/D tilt, and Q/E rotates about Z. Over the view, the mouse wheel zooms toward the cursor and Shift+drag pans. Labels share the colours of the axes drawn in the view. Ground grid
Dim lines every 25 mm on the base plane (z = 0), reaching 1.5 times the base radius, for scale.
Servo arcs
Off by default. Each servo's allowed travel, drawn as an arc of horn length about its base anchor, with ticks at both stops and a marker at the current horn angle. Grey normally, yellow within 5° of a stop, red when the requested pose breaks that servo's range.
Joint cones
Off by default. The cone each ball joint allows at the current pose, with its tip at the rod end; the rod must stay inside it. Same grey, yellow and red scheme. It shows the joint limit only, not collisions.
Workspace box
Off by default. The requirement X, Y and Z ranges as a box around the home pose: the region the platform origin must reach. Rotation ranges are not drawn. It appears when the layout comes from an optimizer run, or from simulator JSON that carries ranges or a run.
Reachability cloud
Off by default because it costs evaluator time. Samples platform positions inside the requirement X, Y and Z ranges (or ±100 mm where there is none) at the current requested rotation and checks each with the same evaluator as the optimizer: green dots are reachable, dim red ones are not. It shows the evaluated samples only, not a continuous boundary, and restarts whenever the rotation, geometry or limits change. Z slice only samples one plane at the chosen Z offset from home instead of the whole box.
Conditioning ellipsoid
Off by default. An ellipsoid at the platform centre showing how strongly the servos drive and hold the platform in each translation direction at the current pose. Its longest axis is drawn as long as the platform axes; a short axis is a direction the servos barely control, so the ellipsoid flattens as the pose nears a singularity. Its colour runs from light blue (well conditioned) to yellow as the condition number worsens, reaching yellow at the condition limit when one is set, and turns magenta when the requested pose fails a conditioning check. The shape covers translation only; the colour also reflects rotation.
Loads
Off by default, and unavailable until the layout comes with a payload: a candidate from a run, or simulator JSON with a load model. Each rod is shaded by the force it carries at the accepted pose, toward blue when it pushes on the platform (compression) and toward orange-red when it pulls (tension), fully coloured when one rod carries the whole static payload weight. Each servo with a torque rating gets a thick band outside its travel arc: it grows from mid-travel toward the stop in the torque's direction and reaches the stop at the rated torque, shading from green to yellow, and turns red above the rating. Loads are static for a manual pose and include the motion while an animation plays; the Pose diagnostics table lists the numbers.
Rejected pose ghost
When a requested pose is rejected, a dimmed outline of that pose beside the held accepted pose. Failing legs are red, and a whole-platform failure outlines it in magenta.
Platform axes
The platform's own X (red), Y (green) and Z (blue) directions at the accepted pose.
World axes
The fixed X (red), Y (green) and Z (blue) axes at the origin, 30 mm long.

The toggles are saved with simulator JSON and browser saves.
